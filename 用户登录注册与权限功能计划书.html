1. 目标与范围

目标：为低代码大屏平台构建一套完整的身份认证与权限体系，支撑「游客不可访问 → 注册/登录 → 按角色与权限使用平台功能 → 管理员管控用户与角色」的闭环。

本期范围：

  • 后端注册、登录（JWT 双令牌）、刷新令牌、当前用户信息、登出。
  • 后端RBAC：角色、权限码、用户-角色关联；角色/用户管理接口受守卫 + 权限装饰器保护。
  • 前端登录页、注册页、Token 持久化与请求拦截器、路由守卫、401 自动登出、按权限隐藏元素、用户菜单。
  • 零依赖密码哈希与 JWT 均基于 Node 内置 crypto 实现，不引入 passport / bcrypt / jsonwebtoken，规避离线环境的安装与编译风险。

范围说明（重要）：为避免一次性改造破坏既有 20+ 模块，本期将鉴权守卫作用于新建的 Auth 与 RBAC 模块（用户/角色管理接口），并在前端做「应用级登录门禁」。既有业务模块（大屏、组件中心、AI 等）的全局鉴权作为后续步骤，可通过把 JwtAuthGuard 提升为全局守卫 + 给公开接口加 @Public() 一键开启。

2. 总体架构

前端登录/注册
→
POST /api/auth/login|register
→
AuthService 校验 + 签发 JWT
→
前端存 Token（localStorage）
前端请求带 Authorization
→
JwtAuthGuard 解析并挂载 user
→
RolesGuard 校验 @Roles/@RequirePermissions
→
受保护接口返回数据

令牌策略：AccessToken（短时效，默认 2h，放请求头）+ RefreshToken（长时效，默认 7d，用于无感续期）。Payload 预计算 roles 与 perms，避免在每次请求中回查数据库。

3. 数据模型设计

在既有 schema.prisma 上扩展，保持 SQLite 兼容（无原生 enum/Json，统一用 String；权限列表以 JSON 字符串存储）：

model User {
  id           String   @id @default(uuid())
  email        String   @unique
  name         String
  passwordHash String?            // scrypt: salt:hash
  status       String   @default("active")  // active | disabled
  lastLoginAt  DateTime?
  roles        Role[]              // 隐式多对多
  orgId        String?
  screens      Screen[]
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt
}

model Role {
  id          String   @id @default(cuid())
  code        String   @unique      // super_admin | admin | editor | viewer
  name        String
  description String?
  permissions String   @default("[]") // JSON: ["user:manage","role:manage",...]
  isSystem    Boolean  @default(false)
  users       User[]                  // 隐式多对多
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
}

关系：User ⇄ Role 为隐式多对多（Prisma 自动生成中间表）；Role 的 permissions 为权限码数组的 JSON 字符串。

4.2 密码哈希（Node crypto，零依赖）

// password.util.ts
import { randomBytes, scryptSync, timingSafeEqual } from 'crypto'
export function hashPassword(pwd: string): string {
  const salt = randomBytes(16).toString('hex')
  const hash = scryptSync(pwd, salt, 64).toString('hex')
  return `${salt}:${hash}`
}
export function verifyPassword(pwd: string, stored: string): boolean {
  const [salt, hash] = stored.split(':')
  const h = scryptSync(pwd, salt, 64)
  const hh = Buffer.from(hash, 'hex')
  return h.length === hh.length && timingSafeEqual(h, hh)
}

4.3 JWT 工具（HMAC-SHA256，零依赖）

// jwt.util.ts
import { createHmac, timingSafeEqual } from 'crypto'
const b64 = (s: string|Buffer) => Buffer.from(s).toString('base64url')
function sign(payload: object, secret: string, expSec: number) {
  const body = { ...payload, iat: Math.floor(Date.now()/1000), exp: Math.floor(Date.now()/1000)+expSec }
  const h = b64(JSON.stringify({ alg:'HS256', typ:'JWT' }))
  const p = b64(JSON.stringify(body))
  const sig = createHmac('sha256', secret).update(`${h}.${p}`).digest('base64url')
  return `${h}.${p}.${sig}`
}
function verify(token: string, secret: string): any {
  const [h,p,s] = token.split('.'); if(!h||!p||!s) throw new Error('bad token')
  const sig = createHmac('sha256', secret).update(`${h}.${p}`).digest('base64url')
  if (sig.length!==s.length || !timingSafeEqual(Buffer.from(sig), Buffer.from(s))) throw new Error('bad sig')
  const payload = JSON.parse(Buffer.from(p,'base64url').toString())
  if (payload.exp < Math.floor(Date.now()/1000)) throw new Error('expired')
  return payload
}

4.4 守卫与装饰器

  • JwtAuthGuard：从 Authorization: Bearer <token> 解析，失败抛 401；成功把 payload 挂到 req.user。
  • RolesGuard：读取 @Roles('admin') / @RequirePermissions('user:manage') 元数据，比对 req.user.roles 与 req.user.perms，不匹配抛 403。
  • @Public()：标记接口跳过 JwtAuthGuard（登录/注册/刷新/开放能力）。
  • @CurrentUser()：在控制器方法参数中注入当前用户。

应用方式：AuthController 与 RbacController 在类上挂 @UseGuards(JwtAuthGuard, RolesGuard)；登录/注册/刷新方法再叠加 @Public()。不污染既有 20+ 模块。

5. 权限模型与角色设计

权限码采用 resource:action 命名（参考 AWS IAM / Casbin）：

资源动作权限码示例
用户查看 / 管理user:view user:manage
角色查看 / 管理role:view role:manage
大屏查看 / 编辑 / 发布screen:view screen:edit screen:publish
组件查看 / 管理widget:view widget:manage
系统参数 / 日志 / 监控system:params system:logs system:monitor

默认角色

角色权限说明
super_admin全部（*）系统内置，不可删
admin用户/角色/系统/大屏/组件 全部管理平台管理员
editor大屏/组件 编辑与查看，无用户/角色管理内容编辑
viewer仅 *:view只读访客

super_admin 与 admin 列为系统角色（isSystem=true），super_admin 不可删除；权限校验支持通配符 * 表示全部。

6. 前端设计

  • 存储src/auth/store.ts（zustand）持久化 token / refreshToken / user / perms 到 localStorage。
  • 拦截器src/api/client.ts 的 request() 自动携带 Authorization；收到 401 清除 token 并跳转 /login。
  • 门禁src/App.tsx：无 token 时渲染 LoginPage；登录后进入 ProjectView。
  • 路由/login /register 加入 featurePages，RequireAuth 包裹受保护内容。
  • 权限组件<Can perm="user:manage">…</Can>：无权限时渲染 null（或 fallback）。
  • 用户菜单顶部栏头像下拉：显示当前用户/角色、登出；菜单项按 perms 显隐（如「用户管理」「角色管理」仅管理员可见）。

7. 接口契约

方法路径公开权限说明
POST/api/auth/register✅—{email,name,password} → {user}
POST/api/auth/login✅—{email,password} → {accessToken,refreshToken,user}
POST/api/auth/refresh✅—{refreshToken} → {accessToken,refreshToken}
GET/api/auth/profile❌登录即可返回当前用户信息 + 角色 + 权限
POST/api/auth/logout❌登录即可前端清 token（无状态）
GET/api/rbac/roles❌role:view角色列表
POST/api/rbac/roles❌role:manage新建角色
PATCH/api/rbac/roles/:id❌role:manage改名称/描述/权限
DELETE/api/rbac/roles/:id❌role:manage删角色（系统角色禁止）
GET/api/rbac/users❌user:view用户列表（含角色）
PATCH/api/rbac/users/:id/roles❌user:manage分配角色
PATCH/api/rbac/users/:id/status❌user:manage启停账号

统一响应信封：{ code, data, message }（code=0 成功）。401/403 由守卫直接返回（兼容既有 client.ts 的拦截逻辑）。

8. 种子数据

9. 落地步骤与验证

  1. 后端：扩展 schema.prisma（User 字段 + Role 模型）→ prisma generate + prisma db push。
  2. 后端：实现 utils / decorators / guards / AuthModule / RbacModule，注册进 app.module.ts；修复 @prisma/client 客户端副本（沿用既有 cp 方案）。
  3. 后端：scripts/seed-auth.mjs 灌入角色与账号。
  4. 前端：store.ts / client.ts 拦截器 / 登录注册页 / 门禁 / Can 组件 / 用户菜单 / api 方法。
  5. 验证：tsc --noEmit + vite build（前端）；nest build 或 tsc -p tsconfig.build.json（后端）；起服务用 curl 跑通「注册→登录→带 token 调 profile→无 token 返回 401→超权返回 403」。

验收标准：未登录访问 /api/rbac/* 返回 401；viewer 访问 role:manage 接口返回 403；admin 正常；前端登录后按权限显隐菜单、登出后跳登录页。

10. 安全与后续演进

  • 全局鉴权一键开启：将 JwtAuthGuard 提升为 APP_GUARD，并为既有公开接口（开放能力、seed 等）补 @Public()。
  • 刷新令牌安全：本期 RefreshToken 为无状态 JWT；后续可改为服务端存储（Redis/DB）支持吊销。
  • 密码策略：注册增加强度校验（长度/复杂度）与邮箱唯一提示；支持找回密码。
  • 审计：登录/权限变更事件写入既有 Audit 模块，形成安全审计轨迹。
  • 多租户：利用既有 orgId 字段做组织级数据隔离。
