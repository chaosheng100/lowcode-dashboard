一、设计总则（企业级规范）

规范性：所有路由遵循统一的路径命名、文件同构与章节结构；前端路由 id 与后端 path 严格一致， 便于权限下发、埋点与自动化测试对齐。

可扩展性：一级路由为业务域容器，二级路由为具体能力；新增能力只需在对应域下挂载二级路由并注册组件， 不影响其他模块。扩展能力（报表/孪生/插件等）均按独立微服务/微前端隔离。

安全性：全链路 RBAC（前端守卫 + 后端鉴权 + 审计）；敏感凭据统一存 KMS，前端仅持引用并掩码展示； 所有写操作二次确认并留痕；外部系统跳转经 SSO 网关签发短时票据。

角色体系（RBAC）

角色 Key名称职责范围

01

大屏管理 /dashboard

一级路由
1. 路由名称与路径

/dashboard  ·  大屏管理

命名规范：路径采用小写 kebab-case，按业务域分层 /<domain>/<feature>；路由 id 与 path 一致（稳定唯一）；菜单名使用中文名词短语，二级继承一级域前缀；对应前端文件 src/route/<domain>/<Feature>.tsx。

2. 功能描述

平台核心工作区，承载可视化大屏的查看、编辑与发布。使用场景：设计师在画布上拖拽组件编排大屏；运营与访客在大屏墙/指挥中心查看实时数据；管理员统一管控大屏生命周期。

3. 页面 / 接口布局

模块：大屏列表（缩略图卡片）、画布编辑器、组件面板、属性面板、数据源绑定面板、发布面板。
关键组件：GridCanvas、WidgetPalette、PropertyInspector、LayerTree、PreviewModal。
数据结构：Dashboard { id, name, slug, layout[], components[], themeId, status, ownerId, updatedAt }；ComponentInstance { id, type, x, y, w, h, props, bindings[] }。

4. 权限控制（RBAC）

采用基于角色的访问控制（RBAC）：角色经「用户管理」绑定，权限点以 route:<path>:read/write 粒度下发。前端路由守卫（beforeEnter）做一级拦截，后端接口做二级鉴权，越权返回 403。 菜单按角色可见性动态渲染，未授权路由不出现在导航树中。

可访问角色：

超级管理员 平台管理员 大屏设计师 数据分析师 运营人员 审计员 只读访客

5. 数据交互

接口：GET /api/dashboards（分页/筛选）、POST /api/dashboards、PUT /api/dashboards/:id、GET /api/dashboards/:id/snapshot。
数据流：服务端状态用 React Query 缓存；画布编辑态用 Zustand（撤销/重做栈）；组件 props 走受控表单并乐观更新。
状态管理：设计态与预览态共享同一 schema，发布时生成不可变快照。

6. 异常处理

画布组件加载失败降级为占位骨架；数据源断连时图表展示「数据暂不可用」并保留上次缓存；保存冲突（他人已修改）弹出版本对比并提示合并；超 500 组件时提示性能风险并建议拆分。

7. 性能考量

路由级 React.lazy 懒加载编辑器包；组件清单虚拟滚动；大屏快照与缩略图 CDN 缓存；编辑态 websocket 增量同步，避免全量重绘；列表接口游标分页 + 30s 软缓存。
